# 片刻后续开发计划

## 1. 执行原则

后续开发不再以“做一个页面”为任务，而以可验证的纵向能力为单位。每项能力按固定顺序推进：

```text
产品规则
  -> 数据模型
  -> API 契约（需要网络时）
  -> 后端实现与测试
  -> Android 领域与数据层
  -> Android UI
  -> 自动化测试
  -> 模拟器验收
  -> 独立提交并推送
```

未经当前里程碑验收，不进入下一阶段。

## 2. 当前基线

已经完成：

- Android 主要页面原型和统一视觉语言；
- 日记采集状态机与本地恢复；
- 日记采集期间固定回复“收到”；
- Android 到本机 AI 网关的普通聊天；
- 聊天发送中、失败和重试；
- 后端与 Android Git 仓库隔离。

尚未完成的关键闭环：

- 可靠本地数据库；
- 真实结构化日记生成；
- 草稿编辑与装订；
- 导出图片；
- 发布级隐私与自动化测试。

## 3. 里程碑总览

| 里程碑 | 目标 | 完成后可证明 |
| --- | --- | --- |
| M0 文档与冻结 | 统一范围、架构和接口 | 团队按同一套方案开发 |
| M1 Android 基础层 | Room、Repository、feature 状态 | 数据可靠，代码可继续扩展 |
| M2 后端 v1 | 正式 AI 网关与生成接口 | 后端可被契约测试验证 |

## 5. M1：Android 基础层重构

M1 不增加新页面。目标是让已有数据不再依赖 SharedPreferences JSON，并拆开全局 ViewModel。

### M1.1 建立 Room schema

- 添加 Room；
- 创建 moments、chat_messages、personas、diary_sessions、drafts、journals、favorites 表；
- 使用 UUID、Instant 和 LocalDate；
- 添加 DAO、索引、事务和数据库测试；
- schema 导出进入仓库。

提交：`feat(data): establish room persistence schema`

### M1.2 迁移旧数据

- 读取当前 SharedPreferences JSON；
- 在事务中迁移到 Room；
- 迁移失败不清空数据；
- 空数据库只在首次安装注入演示数据；
- 添加迁移和重复执行测试。

提交：`feat(data): migrate legacy local records to room`

### M1.3 建立 Repository 与 AppContainer

- 定义 Moment、Chat、Diary、Journal、Persona Repository；
- LocalDataSource 与 RemoteDataSource 分离；
- 使用显式 AppContainer 装配依赖；
- Domain Model、Entity 和 DTO 分离；
- 删除 UI 对 `MomentaryStore` 的直接依赖。

提交：`refactor: introduce repositories and application container`

### M1.4 按 feature 拆 ViewModel

- TodayViewModel；
- ChatViewModel；
- DiaryViewModel；
- JournalViewModel；
- SettingsViewModel；
- 导航只传 ID，不传完整可变对象。

提交按 feature 分开，不一次性重写全部。

M1 验收：

1. 升级安装后原记录、聊天、角色和日记仍存在；
2. 删除全部数据后不会再次出现演示数据；
3. 应用被杀死后状态恢复；
4. 新业务实体不再写入 SharedPreferences JSON；
5. 单元测试、Room 测试、Debug 构建和 Lint 通过。

## 6. M2：正式后端 v1

后端代码只在本机 `backend/` 开发，不提交到 Android GitHub。完成一个后端任务时只做本地提交或另建私有仓库，不混入 Android 提交。

### M2.1 重建 Spring Boot 基线

- Java 21 + Spring Boot；
- 模块：common、provider、chat、diary；
- 统一请求 ID、错误体、校验与超时；
- 环境变量配置供应商 URL、Key 和模型；
- 禁止日志记录正文和 Key；
- 实现 `/api/v1/health`。

### M2.2 陪伴聊天 v1

- 按 API 契约实现 `/api/v1/chat/completions`；
- 服务端构建安全规则和角色 Prompt；
- 消息、角色和总负载长度限制；
- 幂等键、超时和安全错误映射；
- Provider 使用 WireMock 类测试验证。

### M2.3 结构化日记生成

- 实现 `/api/v1/diary-drafts:generate`；
- 固定 JSON Schema；
- 校验所有 source IDs；
- 最多一次格式修复；
- 禁止虚构和心理诊断的系统规则；
- 覆盖空输入、超长、上游失败、非法 JSON 和幂等测试。

### M2.4 本地部署配置

- 开发 profile 与 `.env` 示例；
- 健康检查；
- Android 模拟器联调说明；
- 生产 profile 只允许 HTTPS；
- 上线前门禁明确标注认证、限流和隐私要求。

M2 验收：

1. 所有 v1 契约测试通过；
2. 日记生成返回可解析且来源合法的结构化结果；
3. 上游错误不泄漏供应商信息；
4. 日志中搜索不到日记正文、Authorization 和 API Key；
5. 旧 Node 验证代码被删除，不保留双轨实现。

## 7. M3：真实日记闭环

### M3.1 Android v1 网络层

- Retrofit/OkHttp/Kotlin Serialization；
- v1 DTO 与错误映射；
- 聊天迁移到新接口；
- MockWebServer 契约测试；
- 删除 `HttpURLConnection` 和旧 `/api/chat` 调用。

提交：`refactor(network): adopt versioned momentary api client`

### M3.2 DiaryDraft 领域与持久化

- 实现草稿、摘要块、待办和来源引用；
- 生成前固化来源快照；
- 草稿 revision 和生成状态持久化；
- 应用重启后恢复 GENERATING/REVIEWING；
- 失败后保留来源并允许重试。

提交：`feat(diary): persist source-backed diary drafts`

### M3.3 调用真实日记生成

- 结束日记后进入真实异步生成；
- 展示生成中、超时和失败状态；
- 使用相同 Idempotency-Key 重试；
- 成功后保存草稿再进入审阅页；
- 不允许重复点击创建多个草稿。

提交：`feat(diary): generate structured draft from daily moments`

### M3.4 草稿审阅编辑

- 标题、正文、摘要、愿望、感谢、洞察可编辑；
- 待办可添加、删除和勾选；
- 可查看摘要来源；
- 离开未保存草稿时提示；
- AI 内容和用户修改状态有区分。

提交：`feat(diary): add editable draft review`

### M3.5 装订正式日记

- 在 Room 事务中保存 Journal 并完成 session；
- 同一天重复装订保持幂等；
- Journal 保存最终内容和 draft 来源；
- 总结页不再包含任何硬编码业务文本。

提交：`feat(journal): bind reviewed draft into local journal`

M3 端到端验收：

1. 开始日记并记录三条内容；
2. 杀死应用后恢复采集；
3. 结束后调用真实本机后端；
4. 断网失败时记录不丢失，可重试；
5. 编辑草稿并装订；
6. 重启后可在日记本阅读最终版本；
7. 每条事实摘要能查看来源。

## 8. M4：导出与阅读

### M4.1 阅读页完善

- 使用真实 Journal 数据；
- 支持正文编辑、收藏和来源查看；
- 超长内容、字体放大和深色模式无截断。

### M4.2 完整日记长图

- 专用 Export Composable；
- 1080px 输出和超长分页；
- MediaStore 保存；
- 预览、导出进度和失败处理。

### M4.3 摘录卡片

- 从用户片刻或 AI 回复创建卡片；
- 最多三套固定模板；
- 支持作者标签使用“我”或角色名，不冒充真实作家。

M4 验收：三种长度日记在两种屏幕尺寸上导出无裁切，图片可从系统相册打开。

## 9. M5：稳定、隐私与数据控制

- AI 数据发送说明与首次确认；
- 清空数据、导出备份和恢复；
- Android Backup 明确配置；
- Crash 日志脱敏；
- 网络超时、重试和取消；
- 应用锁评估与 BiometricPrompt；
- 核心 Compose UI 自动化；
- 数据库 migration 回归测试；
- 性能检查：1000 条片刻、300 篇日记、长聊天列表。

## 10. M6：小范围测试版

- 应用名称、图标、版本和签名；
- Release HTTPS 网关；
- 服务端认证、限流、每日额度和成本告警；
- 隐私政策、AI 说明和反馈入口；
- Crash/ANR 监控但不采集正文；
- 5 到 20 名测试者的反馈闭环。

云同步、账号和对象存储仍不属于 M6，除非小范围测试明确证明它们阻塞使用。
