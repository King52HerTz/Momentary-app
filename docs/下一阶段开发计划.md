# 片刻 v0.3：日记采集与生成闭环

## 当前阶段

`v0.2` 已完成并进入 `main`：

- 快速记录、心情选择、今日时间线与本地持久化。
- 三种内置陪伴角色、自定义角色、独立对话流。
- 收藏 AI 回应、收录到今日、装订日记。
- 今日、聊天、总结、日记、回响和个人页的统一纸张视觉系统。
- 单元测试、Debug APK 构建与 Android Lint 验证。

当前仍是可交互的本地原型。总结内容主要由界面静态组织，尚未形成用户最初设想的“开始日记—持续收集—结束生成—编辑装订”完整流程。

## v0.3 阶段目标

把零散记录变成一套可恢复、可编辑、可测试的日记工作流：

1. 用户主动开始某天的日记采集。
2. 采集期间输入文字时，陪伴者只回复“收到”。
3. 用户结束日记后，系统根据当天片刻与收录对话生成完整日记。
4. 同时生成事件、状态、灵感、愿望、感谢、待办与生活洞察。
5. 用户确认或编辑内容后，再装订到日记本。

## 下一项开发任务

### T1：持久化日记会话状态机

这是下一次开发首先实现的功能，单独提交。

新增状态：

- `IDLE`：当天尚未开始日记。
- `COLLECTING`：正在采集，新增内容只回应“收到”。
- `GENERATING`：正在整理当天内容，禁止重复结束。
- `REVIEWING`：生成完成，等待用户编辑或装订。
- `COMPLETED`：当天日记已装订。

需要实现：

- “开始今天的日记”入口与简短鼓励开场。
- 采集状态提示、开始时间和已收集条数。
- 采集期间的输入写入当天记录，AI 固定回复“收到”。
- “结束今天的日记”二次确认。
- 应用重启后恢复当天会话状态。
- 日期变化时不把前一天的采集状态误带到今天。

验收标准：

1. 开始日记后连续输入三条内容，每条只收到“收到”。
2. 退出并重新打开应用，仍处于采集状态，已有内容不丢失。
3. 重复点击开始或结束不会创建重复会话。
4. 状态转换有单元测试，非法转换会被拒绝。
5. `testDebugUnitTest`、`lintDebug`、`assembleDebug` 全部通过。

建议提交：`feat: add persistent diary session state machine`

## 交互原则

- 记录时保持低打扰，不追问、不分析，不抢走用户表达节奏。
- 结束生成前明确告诉用户会整理哪些内容。
- AI 产物始终是草稿，用户拥有最终编辑权。
- 洞察使用支持性语言，不做心理诊断，不制造确定性结论。
- 失败时保留原始记录，任何生成错误都不能导致内容丢失。

## 不在 v0.3 范围

- 正式大模型与服务端代理：安排在 `v0.4`。
- 日记长图、摘录卡片和系统分享：安排在 `v0.4`。
- Room、数据库加密、应用锁和云同步：安排在 `v0.5`。
- 全文搜索、月度回顾和情绪趋势：安排在数据结构稳定之后。

## 开发与提交规则

每个任务按以下顺序完成，不把多个功能压进一个提交：

1. 实现领域模型和业务逻辑。
2. 补充对应单元测试。
3. 接入 Compose 界面并完成模拟器检查。
4. 运行 `testDebugUnitTest`、`lintDebug`、`assembleDebug`。
5. 创建一个语义明确的提交并推送到 GitHub `main`。
