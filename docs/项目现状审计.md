# 项目现状审计

审计基线：`main` 分支提交 `39edc04`。

## 1. 结论

当前项目是“视觉完成度较高的可交互 Android 原型”，不是可长期使用的第一版产品。它已经证明主要页面和日记采集状态机可以运行，但数据模型、生成流程和后端仍不足以支撑真实闭环。

现在应停止继续堆页面，先完成客户端基础层和日记生成纵向链路。

## 2. 已真实完成

- Kotlin + Jetpack Compose 单模块 Android 应用可构建运行；
- 今日、聊天、总结、日记本、日记详情、回响和个人页已存在；
- 快速记录、心情、收藏、收录到今日和自定义角色可交互；
- 日记会话具备 `IDLE -> COLLECTING -> GENERATING -> REVIEWING -> COMPLETED` 状态约束；
- 日记采集状态和内容可在应用重启后恢复；
- 普通聊天可调用可配置 AI 网关，并有发送中、失败和重试状态；
- API Key 没有写入 Android 客户端；
- 已有少量领域与安全边界单元测试；
- Debug、Release、Lint 和模拟器 HTTP 往返曾完成验证。

## 3. 尚未真实完成

### 日记生成是假的

- 结束日记后没有调用生成服务；
- `GENERATING` 状态会立刻切换到 `REVIEWING`；
- 总结页仍根据硬编码文本和简单列表拼接展示；
- 没有 `DiaryDraft`、来源引用、生成失败或再次生成。

### 本地存储不适合继续扩展

- 所有数据以 JSON 字符串保存在 SharedPreferences；
- 没有 schema 版本、迁移、事务、查询和索引；
- 任意一类 JSON 解析失败会退化为空列表，用户难以察觉数据损坏；
- 日期、时间与展示字符串混在模型里；
- 删除全部内容后，演示数据可能再次被注入；
- 没有备份、导入、加密或数据删除策略。

### 客户端结构已经开始拥挤

- 单个 `MomentaryViewModel` 同时负责今日、聊天、角色、日记和存储；
- UI、领域模型、持久化模型和 API DTO 尚未分离；
- `HttpURLConnection`、JSON 组装和错误映射集中在一个类中；
- 页面主要按文件聚合，不按 feature 明确所有权；
- 没有 Repository、UseCase 或 AppContainer 边界。

### 后端只是验证代码

- 当前是 Node.js 内置 HTTP 模块写成的最小网关；
- 只有健康检查和聊天接口；
- 没有 `/api/v1` 版本、统一错误体、请求 ID 和结构化日志；
- 没有认证、限流、配额、超时控制、重试策略或部署方案；
- 没有日记生成 JSON Schema 与结果校验；
- 角色字段由客户端提交，缺少长度与策略级白名单；
- 当前实现只能用于本地联调，不能直接暴露到公网。

### 测试覆盖不足

- 没有 Store 迁移测试；
- 没有 ViewModel 异步状态测试；
- 没有 API 契约测试；
- 没有 Compose UI 流程测试；
- 没有“记录 -> 生成 -> 编辑 -> 装订”的端到端测试；
- 模拟器验证依赖人工坐标操作，尚未自动化。

## 4. 文档冲突

早期方案选择 `Flutter + Riverpod + Spring Boot + MySQL`，实际实现是 `Kotlin + Compose + Node.js`。两套路线并存会让后续任务无法判断应该复用还是推倒。

从本次整理开始，唯一有效路线是：

- Android：Kotlin + Jetpack Compose；
- 本地数据：Room + DataStore；
- 网络：版本化 REST JSON，聊天流式输出后置；
- 后端目标：Java 21 + Spring Boot 模块化单体；
- 第一版：本地优先、无账号、无云同步；
- 仓库：Android 公开仓库与本机后端工作区分离。

## 5. 优先级

### P0：不处理就不能继续

1. 冻结 API 契约和数据模型。
2. 引入 Room，迁移现有本地数据。
3. 拆分大 ViewModel 和 Repository 边界。
4. 实现真实结构化日记生成与草稿持久化。
5. 用真实草稿驱动总结页。

### P1：第一版发布前必须处理

1. 编辑与装订幂等性。
2. 导出图片和相册保存。
3. 网络错误、超时和离线状态。
4. 隐私说明与 AI 发送范围提示。
5. 核心端到端自动化测试。

### P2：闭环稳定后再处理

1. 应用锁与本地加密。
2. 数据备份恢复。
3. 角色编辑与归档。
4. 周度回顾、搜索和统计。

## 6. 立即停止的做法

- 不再新增静态假页面；
- 不再把新的业务状态塞进全局 `MomentaryUiState`；
- 不再用 SharedPreferences JSON 保存新增业务实体；
- 不在 API 契约前同时改客户端和后端；
- 不把 API Key、共享密钥或公网地址硬编码进 APK；
- 不为未来云同步提前引入微服务、Redis 或复杂账号系统；
- 不把多个独立功能压进一个提交。
