# 片刻项目文档

本目录是项目开发的唯一有效文档入口。发生冲突时，以本文档列出的顺序为准，不再以早期脑暴稿或原型截图作为实现依据。

## 阅读顺序

1. [产品计划书](产品计划书.md)：产品为谁解决什么问题，第一版做什么、不做什么。
2. [项目现状审计](项目现状审计.md)：现有代码真实完成度、技术债与必须停止扩建的部分。
3. [Android 技术方案](Android技术方案.md)：客户端目标架构、数据层、状态管理和测试策略。
4. [API 契约 v1](API契约-v1.md)：Android 与后端唯一共享的请求、响应和错误规范。
5. [下一阶段开发计划](下一阶段开发计划.md)：按依赖顺序排列的里程碑、任务和验收标准。
6. [开发流程](开发流程.md)：分支、提交、测试、文档更新和完成定义。
7. [UI 重设计规范](UI重设计规范.md)：视觉方向、令牌和页面规则。

## 文档边界

- GitHub 仓库只保存 Android 代码、共享 API 契约和客户端相关文档。
- `backend/` 是本机后端工作区，已被 Git 忽略，不进入 Android 仓库。
- 后端内部技术方案位于 `backend/docs/后端技术方案.md`，只在本机维护。
- `初步设计方案.md` 是早期脑暴档案，技术选型已经失效，不再作为开发依据。
- 原型图用于表达视觉偏好，不等于完整交互规格。

## 变更规则

- 先修改产品范围或 API 契约，再修改代码。
- 一个功能只允许对应一个明确里程碑，不跨阶段偷跑。
- 文档中的“已完成”必须能够由当前代码、测试或模拟器操作验证。
- 未进入计划的想法先进入候选池，不直接插入当前迭代。
